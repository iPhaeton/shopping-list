# Xcode 27 vs. Expo SDK 54 — investigation report, 2026-09-27

Snapshot as of 2026-09-27; not maintained. The KB owns current truth — hand the findings to the
librarian rather than citing this file as current.

## Verdict

**This project cannot run on Xcode 27 while it is on Expo SDK 54.** It builds (with one
setting overridden), but the resulting app is killed by UIKit at launch on iOS 27. The fix upstream
is Expo SDK 57. Until then, the working toolchain is Xcode 26.6 + the iOS 26.5 simulator runtime.

## Findings — three independent Xcode 27 breakages, in the order they surface

### 1. `npm run ios` fails before building: Simulator.app no longer exists

```
CommandError: Can't determine id of Simulator app; the Simulator is most likely not installed on
this machine. Run `sudo xcode-select -s /Applications/Xcode.app`
```

- Xcode 27 ships no `Simulator.app`. `Contents/Developer/Applications/` is gone; the replacement is
  `Contents/Applications/DeviceHub.app`, bundle id `com.apple.dt.Devices`, URL scheme `devices://`.
- `@expo/cli` 54.0.27 hard-codes the old app in four places:
  `start/doctor/apple/SimulatorAppPrerequisite.js` (`id of app "Simulator"`, accepts only
  `com.apple.iphonesimulator` / `com.apple.CoreSimulator.SimulatorTrampoline`),
  `start/platforms/ios/ensureSimulatorAppRunning.js` (`open -a Simulator`, process-name count),
  `start/platforms/ios/AppleDeviceManager.js` (`tell application "Simulator" to activate`),
  `start/platforms/ios/getBestSimulator.js` (`defaults read com.apple.iphonesimulator`).
- No env var or flag skips the prerequisite. The `xcode-select` advice in the message is a red
  herring — `xcode-select -p` was already correct.
- **Fixed upstream in `@expo/cli` 56.1.26, 57.0.27, 58.0.7** (checked): the prerequisite accepts
  `com.apple.dt.Devices`, launch falls back to `open devices://device/open?id=<udid>`, activation
  tries DeviceHub. **Not backported to the `sdk-54` line.**
- `open "devices://device/open?id=<udid>"` was verified to open DeviceHub on the booted simulator.

### 2. The build fails: Xcode 27 rejects deployment targets below iOS 15.0

`xcodebuild … -destination 'platform=iOS Simulator,id=<udid>' build` → `** BUILD FAILED **`, nine
errors of the form:

```
ios/Pods/Pods.xcodeproj: error: The iOS Simulator deployment target 'IPHONEOS_DEPLOYMENT_TARGET' is
set to 12.0, but the range of supported deployment target versions is 15.0 to 27.0.x.
```

- Xcode 26 warned on this; Xcode 27 errors.
- Offending Pods targets (own podspec minimums, not the project's): `GTMSessionFetcher-…_Core_Privacy`
  (10.0), `AppAuth-AppAuthCore_Privacy`, `GTMAppAuth-GTMAppAuth_Privacy`, `GoogleSignIn-GoogleSignIn`,
  `GoogleUtilities-GoogleUtilities_Privacy` (12.0), `RNSVG-RNSVGFilters` (12.4),
  `RNCAsyncStorage-RNCAsyncStorage_resources` (13.4), `PromisesObjC-FBLPromises_Privacy`,
  `PromisesSwift-Promises_Privacy` (9.0). Mostly resource/privacy bundle targets.
- The app itself targets 15.1 (`ios/Podfile`: `platform :ios, … || '15.1'`; `project.pbxproj`), so
  raising the pods to 15.1 costs nothing.
- **Workaround verified:** passing `IPHONEOS_DEPLOYMENT_TARGET=15.1` on the `xcodebuild` command line
  → `** BUILD SUCCEEDED **`, zero errors. It forces a full rebuild (over half an hour here, no cache reuse).
  A durable fix would be a Podfile `post_install` clamp, which must live in a config plugin because
  `ios/` is gitignored and regenerated by prebuild — not written, since finding 3 makes it moot.

### 3. The built app crashes at launch: iOS 27 requires the UIScene life cycle

Installed with `xcrun simctl install`, launched with `xcrun simctl launch` → two crash reports,
`~/Library/Logs/DiagnosticReports/ShoppingLoop-2026-09-27-171453.ips` and `…-171557.ips`, identical:

```
EXC_BREAKPOINT (SIGTRAP), main thread
UIKitCore  ___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke
UIKitCore  -[UIApplication workspace:didCreateScene:withTransitionContext:completion:]
…
ShoppingLoop.debug.dylib  __debug_main_executable_dylib_entry_point  AppDelegate.swift:6
```

- A deliberate UIKit trap: an app linked against the iOS 27 SDK must adopt the scene-based life
  cycle or it is stopped at launch. The trap is keyed to the SDK the app was linked against, so a
  build made with Xcode 26.6 is not expected to hit it.
- This project has no `UIApplicationSceneManifest` in `ios/ShoppingLoop/Info.plist`;
  `ios/ShoppingLoop/AppDelegate.swift` (SDK 54 template) creates its own `UIWindow` in
  `didFinishLaunchingWithOptions` and starts React Native into it.
- **Fixed upstream only in Expo SDK 57.** `expo` 57.0.25 ships
  `ios/AppDelegates/ExpoAppSceneDelegate.swift`, whose doc comment reads: "Required by the iOS 27,
  which asserts at launch unless the app adopts the scene-based life cycle." It creates the window
  from the `UIWindowScene` and re-feeds URL, user-activity and quick-action events to
  `ExpoAppDelegate`. `expo` 56.0.22 has no such class. Not verified: how SDK 57 switches it on — the
  `expo-template-bare-minimum` 57.0.27 `Info.plist` has no scene manifest either, so it is wired
  elsewhere (prebuild or programmatic configuration).
- Hand-porting scenes onto SDK 54 was rejected: `ios/` is regenerated, and scenes move URL delivery
  from `application(_:open:options:)` to `scene(_:openURLContexts:)`, which the dev-client launch
  link, `expo-linking` and Google Sign-In's redirect all depend on.

## Options

| option | cost | outcome |
|---|---|---|
| **Revert to Xcode 26.6 + iOS 26.5 runtime** (recommended now) | download Xcode 26.6 and ~8 GB runtime; 23 GB free at the time | last known-good setup; no project change |
| **Upgrade to Expo SDK 57** (recommended next, as its own task) | SDK 54 → 57, RN 0.81 → 0.86; three SDKs of migration | fixes all three findings; Apple will eventually require Xcode 27 for App Store submissions |
| Patch `@expo/cli` 54 + clamp deployment targets | `patch-package` dev dep, a config plugin | gets `npm run ios` to a build that still crashes — worthless without scenes |
| Hand-port UIScene onto SDK 54 | native code in a generated folder, URL-forwarding risk | rejected |

## Other things this session touched

- **iOS 26.5 runtime and its 11 simulators deleted** (~17 GB freed). Lost with it: the ability to
  re-check iOS 26-only behaviour, e.g. the react-native-screens dead-back-button bug, which is
  iOS 26-specific and was verified on 26.5. Re-downloadable from Xcode → Settings → Components.
- **The iOS 27 iPhone 17e is new and empty** — no dev build that runs, no signed-in state, no seeded
  data, and its keyboards have not been reset for Maestro.
- Xcode 27 build products now sit in `~/Library/Developer/Xcode/DerivedData/ShoppingLoop-*`.
- An orphaned Xcode 26.6 `Simulator` process (pid 10194) was still running from the deleted bundle
  after the upgrade.
- No project files were changed. `ios/` and `node_modules/` are untouched; every override was
  command-line only.
