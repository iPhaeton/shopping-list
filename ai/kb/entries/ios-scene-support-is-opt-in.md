**The one setting in [app.json](../../../app.json) that keeps the iOS app alive:**
`["expo-build-properties", { "ios": { "enableSceneSupport": true } }]`. It looks optional and is not.

**Why it has to be there.** An app linked against the iOS 27 SDK must adopt the UIScene life
cycle. Without it, UIKit kills it at launch; the crash report's top frame is
`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`. SDK 57 ships the delegate that
does it (`ExpoAppSceneDelegate`) but leaves it **opt-in**. Without the property, the SDK 57
template still creates its own `UIWindow` and hits the same trap. The property needs
`expo` ≥ 57.0.23.

**What it generates** in `ios/` (gitignored, regenerated by prebuild):

- `AppDelegate.swift` conforms to `ExpoReactNativeFactoryProvider`, and its `UIWindow(frame:` and
  `startReactNative` call are gone.
- `Info.plist` gets `UIApplicationSceneManifest`, with `UISceneDelegateClassName` set to
  `EXExpoAppSceneDelegate`. That is Expo's class, used directly, with no subclass in the project.
- The plugin throws on a non-standard `AppDelegate`.

**Rejected: a local config plugin.** The approved plan was a hand-written
`plugins/withIosSceneLifecycle.js`, copied from the SDK 58 preview template. A search of `expo`,
`@expo/prebuild-config`, `@expo/config-plugins` and the SDK 57 bare template found no switch. The
SDK 57 changelog then named this property, in a package that search had not covered. It makes the
same edits. **No project code owns the scene wiring**, so do not add a plugin for it.

**What was checked under scenes** (iPhone 17e, iOS 27):

- It launched with no crash report.
- A cold-start deep link loaded Metro. `ExpoAppSceneDelegate` rebuilds the launch options from
  `connectionOptions`.
- A warm deep link reloaded the app (`openURLContexts`).
- Home and back fired the foreground refetch.
- "Continue with Google" reached the system consent alert, so `GoogleSignInAppDelegate` still gets
  a presenting view controller. A *completed* Google sign-in on iOS is still unrecorded
  ([google-native-signin-library-gaps](google-native-signin-library-gaps.md)).
- `expo-splash-screen` (task 20 step 5): on Release cold starts the launch screen was held and
  hidden from JS as designed, and switched to the app's variant in place.

The delegate re-feeds URL, user-activity and life-cycle events to `ExpoAppDelegate`'s subscribers
(dev launcher, Google Sign-In). A new native module that hooks `application(_:open:options:)`
should work the same way, but check it on a device.

**At SDK 58, remove the property.** The SDK 58 template adopts scenes itself, and there the plugin
only prints a warning that it can be removed. The `verify:` pins `"expo": "~57`, so it fails on that
upgrade on purpose: drop the property, then rewrite this entry or retire it. Any change here is
native: prebuild and rebuild the dev client
([native-build-toolchain](native-build-toolchain.md)).
