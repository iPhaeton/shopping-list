Every **interactive** element is reached through its accessibility props, so those props are
load-bearing, not decoration. Almost every control is a `PillButton`, `IconButton`, `TextField` or
`SegmentedPicker`, so a label usually appears in source as a `label=` or `accessibilityLabel=` prop at
the call site, not on a `Pressable`:

**Match the label the component renders today, not this entry's history.** A query against a stale
string does not fail loudly: it just finds nothing. Sharing's `"Share"` became `"Invite"` in task 28.

**A label that names a row's subject is the escape hatch when one screen renders many of the same
control** — `RolePicker`'s `labelFor`, `` `Accept invitation to ${listName}` ``. Take that route before
`getAllBy*` and an index, which silently follows the wrong row when the order changes. The inverse:
a control whose text moves keeps a fixed label — the resend button counts down (`Resend code in 43s`)
while its label stays `"Resend code"`. Reserve composed labels for where the composition is the
information.

**State shown only by a drawing is exposed as `accessibilityValue`, and asserted through it.** The
magnifier's dot means a search or non-default sort is in effect, and its `summary` value is defined
exactly when the dot shows; the bell's dot pairs with `` `${unread} unread` ``. Assert
`toHaveAccessibilityValue`, never the dot's `View`. **To assert *no* value, match on `text`** —
`not.toHaveAccessibilityValue({ text: expect.anything() })` (or `{ text: /./ }`): RNTL 14's `Pressable`
normalises a missing `accessibilityValue` to an object of `undefined`s. Both screen suites wrap
`SortProvider` around `ListsProvider`, as `App.tsx` does, and press `New list`/`New item` before
typing a name, since search holds the slot at rest.

**A component that renders arbitrary text gets a role but no label.**
[ErrorBanner](../../../src/components/ErrorBanner.tsx) has `accessibilityRole="alert"` and nothing
else: tests assert the string they arranged to fail with (`findByText('permission denied')`).
[SyncBanner](../../../src/components/SyncBanner.tsx) likewise carries only
`accessibilityLiveRegion="polite"`, and three suites assert `"1 change will sync when you're back
online"` / `"2 changes …"` verbatim. Its mount pattern is a separate gotcha
([sync-banner-mount-is-unconditional](sync-banner-mount-is-unconditional.md)).

**Static copy is queried by its visible text.** [EmptyState](../../../src/components/EmptyState.tsx)
carries no accessibility props; tests assert `No lists yet`, `Nothing on this list`, `List not found`,
`ListRow`'s `Shared with you · can edit` / `· view only` subtitle and the sign-in notices
(`You were signed out on another device.` / `Your account was deleted.`) verbatim. Rewording copy is a
test change. Do not "fix" `EmptyState` with a label; nothing queries it that way. Also verbatim:

- **Roles.** `Read only — you can see this list but not change it.`, `Nobody has added anything yet.`,
  `Only an owner can change who has access.`, `A list must keep at least one owner.`, `You need a
  connection to change who has access.`, `You have read-only access to this list.` The last-owner hint
  mirrors the `keep_last_owner` trigger and the read-only line is `useListWrites`' guard word for word.
  Change one half and change the other.
- **The bin.** `That list is in the bin. Restore it and keep your change?` and its item twin; the
  binned-list notice, there because restoring a list does **not** restore its items
  ([deletion-is-a-tombstone](deletion-is-a-tombstone.md)); `Deleted lists, newest first.` /
  `Deleted items, newest first.` in the bar's place; `The bin is empty`. The delete/restore action
  flips its whole label, so `queryByLabelText('Delete Milk')` returning nothing is a real assertion.
- **Limits.** `You own 100 lists. Delete one or hand one over to make room.`, `You're on 1,000 lists.
  Delete or leave one to make room.`, `This list is full: 1,000 items at most.` Suites import them from
  `src/lib/limits.ts`, never from the mocked `listsApi`
  ([supabase-client-module-boundary](supabase-client-module-boundary.md)).

**In the browser, screen-level chrome appears twice.** React Navigation keeps the screen underneath
mounted, so Playwright on List detail finds *two* sync banners — filter by visibility or take
`.last()`. Maestro sees the same ([maestro-drives-the-native-ui](maestro-drives-the-native-ui.md)).

**What to do:** give new interactive components a role, a label, and — if they have on/off state —
an `accessibilityState`. A merely *unavailable* control keeps its role and label and gains `disabled`.
**RNTL's `fireEvent` fires nothing from a disabled element** — not even an event meant for an ancestor,
like a `FlatList`'s `endReached` — so in the bin, where every checkbox is disabled, List detail's tests
scroll from a row's `Restore` instead.

The `verify:` sweeps every non-test `.tsx` with a `<Pressable` for a role and a label, and pins the
labels, values and copy above.
